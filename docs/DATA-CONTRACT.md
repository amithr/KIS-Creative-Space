# KIS Shared Data Contract (web ⇄ Android app)

Identical copy of this file ships in both handoff packages (`design_handoff_kis_web`, `design_handoff_kis_flutter`). It is the single source of truth for the entities both clients read and write. Backend: one shared realtime database (Supabase or Firestore); prototypes stub it with `localStorage` keys noted below.

## Entities

### Item  — prototype key `kis-inventory-v1`
```
Item {
  id: string            // AUTOGENERATED alphanumeric code, e.g. "KIS-7F3K9Q" ("KIS-" + 6 chars,
                        //   ambiguous glyphs excluded). Immutable; assigned at creation; this exact
                        //   string is what the printed QR label encodes. Never user-editable.
  name: string
  note: string          // short description
  area: "LEGO Play" | "Robotics" | "Art & Design" | "VR Lab" | "3D Printing"
  avail: int            // physical units in the space right now (admin-managed)
  total: int            // owned units; 0 ≤ avail ≤ total
  added: timestamp      // drives the NEW badge / "New this week" filter (7 days)
}
```

### SpaceBooking (room schedule) — prototype key `kis-schedule-v1`
One row per period. Multi-period requests may share `requestGroup`. Status carries the approval lifecycle (item reservations are separate and do **not** use this).
```
SpaceBooking {
  id: string
  date: ISO date                 // booking_date in DB
  period: 1–8
  teacherName: string            // "Ms. Bondar — 7B Science"
  purpose?: string
  area?: string                  // e.g. "whole space"
  requestGroup?: string          // shared uuid across multi-period rows
  status: "pending" | "confirmed" | "declined" | "cancelled"
  requestedAt: timestamp
  decidedAt?: timestamp
  decidedBy?: string             // admin identity
  declineReason?: string         // optional one-liner to the teacher
}
```
Rules: public Schedule creates `pending`. Only `pending` and `confirmed` occupy a grid slot. Overlap is allowed with an advisory warning (never hard-block). Confirm/Decline is teacher/admin-only and idempotent.

### SpaceBlock (closed periods) — prototype key `kis-blocks-v1`
Admin-only. Closes schedule cells for a day or weekly recurrence; never deletes bookings.
```
SpaceBlock {
  id: string
  repeat: "once" | "weekly"
  date?: ISO date              // required when once (block_date in DB)
  dow?: "MON"|"TUE"|"WED"|"THU"|"FRI"  // required when weekly
  until?: ISO date             // optional inclusive end for weekly
  from: 1–8                    // period_from
  to: 1–8                      // period_to (from ≤ to)
  reason: string               // shown on the public grid; default "Blocked"
  at: timestamp
}
```
Applicability: `from ≤ period ≤ to`, and once matches `date`, or weekly matches weekday and (`until` null or date ≤ until). Grid precedence: booking → past/out-of-range → blocked → open. Booking requests for blocked slots are rejected server-side.

### Reservation — prototype key `kis-reservations-v1`
One record covers reservations AND walk-up loans; status carries the lifecycle.
```
Reservation {
  id: string
  itemId: string
  qty: int                       // units requested
  by: string                     // "Ms. Bondar, 7B"
  days: ISO date[]               // one or more school days, ≤ 7 days ahead
  periods: "all" | [start, end]  // period range 1–8, or whole day
  status: "reserved" | "out" | "returned"
  outQty: int                    // units currently checked out (0 unless status = out)
  source: "web" | "app"          // web = teacher reservation; app = walk-up check-out
  at: timestamp                  // created
  outAt?: timestamp              // last check-out
  returnedAt?: timestamp         // fully returned
}
```

### ActivityEvent — append-only audit feed
```
ActivityEvent {
  type: "reserve" | "checkout" | "checkin" | "add" | "remove" | "edit" | "sync"
  itemId?: string
  reservationId?: string
  actor: string                  // teacher name or "admin"
  source: "WEBSITE" | "THIS PHONE" | "ADMIN" | "AUTO"
  at: timestamp
}
```

## Who writes what
- **Print files**: `PrintRequest.file_path` points at an object in the public-read `print-files` bucket. It is deleted (and `file_path` set to null) when the job reaches READY and its UNDO window passes, when the job is removed, or when a student cancels at RECEIVED. Both the web admin and the app perform the deletion for their own READY marks; the web admin additionally sweeps jobs READY for over two minutes with a file still attached. Download URL: `<SUPABASE_URL>/storage/v1/object/public/print-files/<file_path>?download=<file_name>`.
- **Web** is now only the student print site plus the Studio Admin print queue: it reads/writes `PrintRequest` and `FilamentColor` and nothing else. The former web teacher admin (space bookings, blocks, inventory, projects, Wednesdays, QR labels) was removed; those tables are owned by the app alone.
- **App** transitions item reservation status: check-out (`reserved → out`, sets `outQty`), check-in (`out → returned` when `outQty` hits 0; partial returns decrement `outQty` and keep status `out`). Walk-up check-outs create a Reservation directly with `status: "out"`, `days: [today]`, `periods: "all"`, `source: "app"`. App also confirms/declines space bookings and does full Item CRUD.
- Both append `ActivityEvent` for item mutations. Both subscribe to realtime on `space_bookings` so confirm/decline syncs instantly.

## Availability math (both clients must agree)
- `Item.avail` is physical stock; reservations do NOT decrement it.
- Free units for item *i* on day *d*, period *p*:
  `free(i,d,p) = i.avail − Σ qty of reservations for i whose days include d, whose periods cover p, and whose status ≠ "returned"`
- Web reservation panel: qty cap = min of `free` over the selected days × periods; a period chip is disabled when its `free` is 0 on any selected day.
- Web Resources table shows an amber OUT band under an item while any reservation for it has status `out` ("3 OUT · Checked out to Ms. Bondar, 7B · due back Fri after P8").

## Sync rules
- Optimistic writes with a local offline queue on the app; last-write-wins per field via server timestamps.
- Both clients subscribe to realtime changes on `items`, `reservations`, `space_bookings`, `activity`; a status change on either side must appear on the other within ~1s when online.

### PrintRequest (student print site v2) — table `print_requests`, migrations 022 + 023
Students are identified by email only. Admin mutations (status, origin, quality, adjust, remove) are admin-only: the web Studio Admin runs them through the service role after a password gate, the Flutter admin through a teacher session (RLS). Students may cancel (delete) only while `status = 0`. Files live in the public-read storage bucket `print-files` under `<token>/<filename>` (50 MB cap).
```
PrintRequest {
  id: string
  kind: "3d" | "poster" | "sticker"
  origin: "mine" | "school" | "found"     // who designed it (student claims; admin can change)
  teacher: string | null                   // required when origin = "school" (id from the teacher list)
  quality: 1 | 2 | 3                       // admin rating, default 1; only meaningful for origin = "mine"
  adjust: int                              // admin manual point adjustments (+10 top-ups), default 0
  name: string; email: string
  file_name: string                        // original filename shown everywhere
  file_path: string | null                 // storage object path; null for seeded rows
  file_size: int
  color: string                            // FilamentColor.v for 3d; "vinyl" for poster/sticker
  qty: int                                 // 1 for 3d; 1–50 for vinyl
  cut: "contour" | "border" | "square" | null   // vinyl only
  status: 0 | 1 | 2 | 3                    // index into the kind's stage list
  ready_at?: timestamp
  created_at: timestamp
}
FilamentColor { v: string (slug, pk); label: string (UPPERCASE); hex: string; on: boolean; sort: int }
Stages — 3d: RECEIVED → SLICING → PRINTING → READY
       — poster/sticker: RECEIVED → PRINTING → CUTTING → READY
```
Points (compute identically on every client — web `src/lib/ledger.ts`, Flutter `lib/data/ledger.dart`):
- start 30; each print costs 10 unless `origin = school` (free); cancelling while RECEIVED refunds (row deleted).
- `ORG = { mine: {base 15, bonus [0,5,10,15]}, school: {base 0}, found: {base 0} }`; `earn = base + bonus[quality]`, paid only at READY.
- `balance = 30 − 10 × non-free prints + Σ earn(READY) + Σ adjust`; `stitches = Σ earn(READY)`.
- Ranks by stitches: Thread 0 · Needle 15 · Stitcher 40 · Weaver 80 · Master Embroiderer 150.
No email is sent at READY; students follow the tracker page.
